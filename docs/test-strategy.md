# Стратегія тестування проєкту (Test Strategy) — Ітерація 3

## 1. Критичні бізнес-сценарії
* **UC-1 (Створення замовлення):** Розрахунок вартості з урахуванням знижок (`Strategy`) та блокування доступності машини.
* **UC-3 (Повернення автомобіля):** Розрахунок пені при несвоєчасному поверненні та відновлення статусу `IsAvailable`.
* **Fault Handling (Робота з файлами):** Стійкість системи до пошкодження JSON-структури на диску.

## 2. Важкі для тестування частини коду
* **Persistence-шар (`JsonDataStore`):** Пряме тестування файлової системи може залишати сміття на диску або викликати конфлікти доступу. Буде вирішено через `Path.GetTempFileName()`.
* **Поліморфна десеріалізація:** Базовий клас `Vehicle` має спадкоємців `PassengerCar` та `Truck`. Тестування повинно гарантувати, що специфічні поля не втрачаються після завантаження.

## 3. Використання Mocks vs Реальній інтеграції
* **Unit Tests:** Використовують заглушки репозиторію (`InMemoryRentalRepository`) для ізольованої перевірки бізнес-правил без торкання жорсткого диску.
* **Integration Tests:** Використовують реальні екземпляри `JsonDataStore`, що пишуть у тимчасові файли, для перевірки наскрізного циклу "Пам'ять ➡️ Диск ➡️ Пам'ять".

## 4. Негативні сценарії (Fault Matrix)
* Оренда автомобіля, який вже зайнятий іншим клієнтом.
* Спроба скасувати або завершити вже закрите замовлення.
* Читання з диска порожнього файлу або файлу із невалідним вмістом (корупція даних).

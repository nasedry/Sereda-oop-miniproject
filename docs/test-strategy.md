# Стратегія тестування (Lab 36)

## 1. Критичні сценарії (Core Use Cases)
* **Розрахунок вартості зі знижками:** Перевірка коректності застосування патерну `Strategy` (`LongTermRentStrategy`, `WeekendStrategy`) для різних часових меж.
* **Життєвий цикл замовлення:** Запобігання паралельного бронювання одного автомобіля, валідація переходів статусів (Active -> Completed/Cancelled).
* **Стійкість збереження стану:** Надійність серіалізації поліморфних колекцій (`Vehicle`, `PassengerCar`) у `JsonDataStore`.

## 2. Зони ризику та тестування
* **Файлове введення-виведення (I/O):** Пряма робота з диском уповільнює тести та може створювати конфлікти доступу до файлів.
* **Рішення:** Для Юніт-тестов застосовано ізоляцію (залежності передаються як `null!` або відносні Safe-Mocks), а для Інтеграційних тестів файли створюються динамічно через системний `Path.GetTempFileName()`.

## 3. Негативні сценарії (Fault Handling)
* Пошкодження структури JSON-файлів конфігурації.
* Повна фізична відсутність файлу бази даних при старті системи.
* Спроби скасування або завершення вже закритих замовлень.
